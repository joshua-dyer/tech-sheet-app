# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Running the App

Static, multi-page site — no build step, no dependencies, no package manifest, no SPA/router. Each sheet type is its own standalone HTML file (`index.html` for Abdominal, `thyroid.html` for Thyroid, `carotid.html` for Carotid, ...), each loading its own tiny entry script as an ES module (`<script type="module">`), so every page must be served over `http://`, not opened via `file://` — use VS Code's Live Server (or any static file server). There are no lint or test commands; verification is manual (exercise each page directly in a browser).

## Architecture

The form is schema-driven and multi-page: adding a sheet type means a new `data/<name>Sheet.js` file, a new `<name>.html` shell, and a matching one-line `js/<name>App.js` entry script — not new engineering in the shared renderer/reveal/print/nav modules below, and not a single-page app (per `DESIGN.md` §5, each sheet stays an independently readable, self-contained page).

**Per-sheet files** (repeat this trio for each new sheet type):
- `data/abdominalSheet.js` / `data/thyroidSheet.js` / `data/carotidSheet.js` — a plain object `{ id, title, sections, groupReveals? }`. Each `section` is `{ id, label, fields, layout?, tableColumns?, tableRows?, printRender?, printRowCount?, fullWidthPrint? }`; each `field` is `{ id, label, type, unit?, options?, reveal?, hiddenByDefault?, row?, defaultValue?, emptyPrintText?, omitPrintLabel?, checkedPrintText?, compute? }`. Each sheet holds the one piece of sheet-specific print logic that doesn't fit the generic engine as a function value directly in this file — Abdominal's Gallbladder/Murphy's Sign, Thyroid's Nodule Table, Carotid's Vessel Panels — see their respective entries below.
- `index.html` / `thyroid.html` / `carotid.html` — near-identical shells (header/toolbar/nav-mount/form-mount/generic-modal markup) per `DESIGN.md` §5 — the boilerplate similarity across sheet pages is intentional, not duplication to clean up; the shared *logic* lives in the JS/data modules, not the HTML.
- `js/app.js` / `js/thyroidApp.js` / `js/carotidApp.js` — a 3-line entry point per sheet: import its schema, import `initSheet`, call `initSheet(schema, sheetId)`. Kept separate from `js/initSheet.js` itself specifically so importing the shared bootstrap has no side effects.

**Shared cross-sheet sections** (not organ-specific — used by every sheet, not just Abdominal):
- `data/demographicsSection.js` — the Demographics section object. `js/printView.js`'s two-column print split (`DEMOGRAPHICS_LEFT_IDS`/`DEMOGRAPHICS_RIGHT_IDS`) depends on these exact field ids, so any sheet importing this section gets that layout for free.
- `data/commentsSection.js` — Technologist Comments. Its field sets `omitPrintLabel: true` since the section heading already states the label.
- `data/interpretationSection.js` — the Physician Interpretation toggle/dropdown/impression fields (imports the roster from `data/physicians.js`). `js/printView.js`'s `renderInterpretationHtml` and its Comments-suppression/print-promotion logic both key off this section's fixed field ids.
- `data/physicians.js` — `PHYSICIAN_NAMES` (roster, currently empty — add names directly to the array) and `OTHER_PHYSICIAN_OPTION` (the manual-entry sentinel used by both the schema and `js/printView.js`).
- `data/sheets.js` — the sheet registry (`[{ id, label, href }]`) driving `js/nav.js`. Add an entry here when a new sheet page is created.

**Shared engine/behavior modules:**
- `js/formRenderer.js` — generic schema → DOM renderer. Dispatches on `field.type` (`text`/`number`/`date`/`select`/`radio`/`checkbox`/`checkbox-group`/`textarea`/`computed`/`diagram`/`dynamic-table`/`static-table`) to build real, natively-focusable semantic elements (`<fieldset>`/`<legend>` for grouped rows and option groups, `<label for>` on every input — no div-based fake controls). `number` fields get `step="0.1"` (measurements are recorded in tenths of a centimeter). A `select` field can set `defaultValue` to pre-select an option other than the blank placeholder (used by the Physician Name dropdown, defaulted to "Other - enter manually"). `diagram` and `dynamic-table` only render their *static* shell here (canvas/controls; table header + Add Row + empty body) — a companion module (`js/diagramMarkup.js`, `js/dynamicTable.js`) does all the runtime wiring, same division of labor as `js/fieldReveal.js` does for reveals. `static-table` is a pure read-only reference display (`{ columns, rows }` of literal strings, no inputs) — deliberately not wired into `getDisplayValue`/`hasValue`/`clearSheet`, since their existing `default` branches already treat an unrecognized type as "no value, nothing to clear," which is exactly "on-screen only, never printed" for free (Carotid's Reference Table). A **section** (not field) can set `layout: 'table'` (plus `tableColumns`: header strings, `tableRows`: `{ label, fieldIds }`) to lay its fields out as a real `<table>` — one `<th scope="row">` + bare cells per row — instead of the default card/field-grid; used for a *fixed* number of rows of otherwise-ordinary, individually-declared fields (Carotid's Right/Left Vessel Panels) where per-field labels would be redundant with the row/column headers. Bare cell controls (`buildInputControl`/`buildSelectControl`/`buildComputedControl`) are factored out of the normal labeled-field renderers specifically so this table path reuses the exact same control construction (including things like `step="0.1"`) rather than duplicating it. Also exports `el` (the tiny DOM-builder helper, reused by `js/dynamicTable.js` for rows built after initial render) and `flattenFields(schema)`, the shared helper other modules use to walk every field regardless of section — `layout: 'table'` fields are declared as perfectly ordinary entries in `section.fields`, so `flattenFields` (and everything built on it — `js/computedFields.js`, `js/clearForm.js`, `js/printHelpers.js`) needs zero awareness of the table layout at all.
- `js/fieldReveal.js` — generic conditional-reveal engine. A field's own `type` determines whether *it* fires reveals on `blur` (text/number/date) or `change` (select/radio/checkbox/checkbox-group) — this mapping is fixed and applies to any schema. Reveal targets are looked up by `field-wrap-<id>` and shown/hidden via the `hidden` attribute (removes them from the tab order and a11y tree) plus a `.is-visible` class that CSS transitions for the animate-in (see the `.reveal-target` grid-rows trick in `css/styles.css`). The Aorta rule (any of three measurements ≥3.5cm) doesn't fit the generic one-trigger-per-field model, so it's handled as a `schema.groupReveals` entry instead — this is the pattern to extend if a future sheet needs another multi-field trigger. Because reveal targets are flat siblings rather than DOM-nested under their trigger, `applyReveal` recurses: revealing a target that itself declares a `reveal` immediately evaluates that nested rule against the target's *current* value (so a `select` defaulted via `defaultValue` to a value that should already show a dependent does so right away, not only after the user changes it), and hiding a target force-closes its own nested targets too so a collapsed branch can't leave one of them orphaned visible.
- `js/computedFields.js` — generic engine for any `computed` field declaring `compute: { dependsOn: [ids], formula: (...values) => result }` (mirrors the `reveal: { targetIds, condition }` shape). Recomputes on blur of any `dependsOn` field, writing `'—'` when the formula returns `null` (a dependency is still blank). One mechanism serves Demographics' Age (date-diff, in `data/demographicsSection.js`), Thyroid's Lobe Volume (`length×width×height×0.479`), and Carotid's CA/CCA Ratio (`icaSystolic÷ccaSystolic`, `null` — displayed as `'—'` — if either is missing or CCA is 0) identically — the math lives in the schema, not here. (This replaced an earlier one-off `js/ageCalculator.js` specific to Age; if you're looking for that file, this is where its logic now lives.)
- `js/diagramMarkup.js` — the shared Diagram Markup feature (`DESIGN.md` §8: freehand red-stroke markup over a fixed reference image, used by `type: 'diagram'` fields — Thyroid's and Carotid's diagrams so far, and meant for a future Arterial sheet too). Nothing about the mechanism constrains strokes to the illustration's own anatomical outlines — only to the canvas element's own rectangle — so Carotid's "unconstrained, may need to mark outside the vessel outlines" requirement was already satisfied with zero new code. `initDiagramMarkup(schema)` wires one independent instance per diagram field via the Pointer Events API (not separate mouse/touch handlers): strokes are discrete undoable point-arrays redrawn from scratch each time (base image + every stroke) rather than flattened while editing, in fixed red. The Enable Markup checkbox gates the pointer handlers and toggles `canvas.style.touchAction` (never set in CSS — see `css/styles.css` — so a disabled diagram never blocks normal touch-scroll); a `document`-level `pointerdown` listener auto-unchecks it when the click/touch lands outside that instance's own canvas/controls. A hidden `<input>` mirrors the current strokes as JSON (empty when none) purely so this non-form-control widget reads like a text field to `js/printHelpers.js` — print itself reads the live canvas via `toDataURL()`, not this mirror. Exports `resetDiagram(fieldId)` for `js/clearForm.js`.
- `js/dynamicTable.js` — generic repeatable-row-table engine for `type: 'dynamic-table'` fields (currently Thyroid's Nodule Table). The row-management/live-computation *mechanism* here is generic; the scoring formula is schema-supplied (`field.scoreColumnIds`, `field.deriveTirads`) — same "generic engine + schema-supplied function" split as `reveal.condition`/`printRender`. `initDynamicTables(schema)` wires Add Row (starts with one, per the always-blank-first-row convention), per-row Delete Row (immediate, no confirmation — deleting a bad row should be faster than clearing it), and a delegated `change` listener that recomputes a row's Total Points (sum of its `score-select` columns' point values, unselected counted as 0) and re-derives its TIRADS-style label live — staying `'—'` until at least one is actually selected, rather than defaulting to a real category before any assessment was made. Like the diagram, a hidden `<input>` mirrors row data as JSON for `js/printHelpers.js`; print reads the live rows directly (see the sheet's own `printRender`). Exports `resetDynamicTable(fieldId)` for `js/clearForm.js`.
- `js/printHelpers.js` — pure, schema-agnostic DOM-value readers with zero dependency on any data file (a leaf module, safe for both `js/printView.js` and per-sheet data files to import without a circular reference): `escapeHtml`, `getDisplayValue`, `getCheckedGroupValues`, `hasValue`, `isFieldVisible`. `getDisplayValue` treats `diagram`/`dynamic-table` fields exactly like a text field — both mirror their real state into a same-id hidden `<input>` (see `js/diagramMarkup.js`/`js/dynamicTable.js`) specifically so this reader needs no special-casing for them.
- `js/printView.js` — the shared print engine. Reads current values straight from the live DOM (no separate app-state object) and writes them into a new window with its own self-contained, print-friendly light theme (deliberately not the app's dark on-screen palette). Since every rule in that stylesheet sizes text in `rem` (relative to that document's own root, not this app's), a single `html { font-size: 14px }` at the top controls the print output's overall text size for every sheet at once — the lever to reach for if a sheet needs to run smaller to fit more on one printed page, rather than hand-tuning individual rules. Any field with no value is dropped from the printout entirely (not shown blank), and a section with nothing to print is skipped along with its heading — unless `emptyPrintText` is defined, a non-diagnostic placeholder for "checked, nothing flagged" (e.g. "No abnormalities noted"); it can live on a single field (a checkbox-group, when nothing is checked) or on the section itself (Pancreas, when none of its several independent fields — measurements or the Poorly Visualized checkbox — have anything entered), and the section-level fallback only kicks in once every field in that section renders no printable row. A field can also set `omitPrintLabel: true` to print its value with no inline label — used on Technologist Comments and (honored separately by the diagram row renderer) Thyroid's diagram field, both cases where the section heading already states the label — or `checkedPrintText` to override a checked checkbox's printed value with its own phrase (Thyroid's Hypervascularity — "Hypervascularity noted" instead of "Hypervascularity: Yes" — combines both flags). A `diagram` field always prints regardless of emptiness (an unmarked reference image is still meaningful context) and renders as a flattened `<img>` via the live canvas's `toDataURL()`, not a label:value row. A section can set `printRender(section)` to fully replace the generic field-row rendering with bespoke markup — **this is the extension point for sheet-specific print quirks**, not another hardcoded section-id check in this shared file (Abdominal's Gallbladder/Murphy's Sign and Thyroid's Nodule Table both use it — see their own data files below) — plus a matching `printRowCount(section)` since the generic row-counter (used to balance the two Findings columns) can't know how many rows a bespoke renderer actually produces. A section can also set `fullWidthPrint: true` to opt out of that two-column balance entirely and render as its own full-width block instead (Thyroid's and Carotid's Diagrams, Thyroid's Nodule Table, and Carotid's Vessel Panels all do — a wide table or a diagram image would be illegible squeezed into a half-page column); such sections are rendered in schema order after the Findings columns and before Technologist Comments. Any sheet-specific `printRender` that builds its own wide table (Nodule Table, Vessel Panels) can use the shared `.print-data-grid` CSS class for consistent print-table styling rather than each defining its own. Layout overall is: Demographics (two fixed columns) plus Physician Interpretation when its toggle is enabled, both full-width up top; then a full-width "Findings" title followed by the remaining non-full-width sections split into two flexbox columns, balanced in JS by a running printable-row-count rather than CSS `column-count` — WebKit's print/PDF engine collapses multicol layouts to a single column during the actual print pass even though they render fine on screen (WebKit bugs 122214, 156300), so this layout must stay off `column-count` entirely; then any `fullWidthPrint` sections; Technologist Comments always trails as its own full-width block at the very end — unless Physician Interpretation is enabled (its toggle checked, not merely non-empty), in which case Interpretation takes the top-of-page spot instead and Comments is suppressed from the printout entirely, regardless of its own content. Interpretation prints even with an empty impression when enabled — that blank space is intentional, flagging a possibly-missed review — with a signature block (a line, then the physician's name beneath it) below the impression text. A divider rule is inserted only between blocks that actually rendered content, including between Demographics and a promoted Interpretation section — with one deliberate exception: a `diagram` field's section always gets a trailing divider even when it's the very last thing printed (nothing trails a large image as cleanly as a text section, visually), so this is the one case where a "stray trailing rule" is intentional rather than something the general block-joining logic avoids. The printed `<h1>` also switches wording based on the toggle: "— Report" when Physician Interpretation is enabled, "— Tech Sheet" otherwise (the browser tab `<title>`, a separate string, is untouched by this).
- **Abdominal's Gallbladder/Murphy's Sign** (`data/abdominalSheet.js`, not `printView.js`): Murphy's Sign is folded into the Gallbladder checkbox-group as a "Positive Murphy's Sign" option rather than its own section, via that section's `printRender`. If checked, the checked findings print as-is (no `emptyPrintText` fallback, since a positive reading is itself an abnormal finding); otherwise "Negative Murphy's Sign" is always appended, whether or not any of the other four boxes are checked.
- **Thyroid's Nodule Table** (`data/thyroidSheet.js`, not `printView.js`/`js/dynamicTable.js`): the five TIRADS scoring categories (Composition, Echogenicity, Taller-than-wide, Margins, Echogenic Foci) and their point values live in one `NODULE_COLUMNS` array here, driving both the on-screen dropdown options ("Solid (2 pts)") and the on-screen Scoring Key so they can't drift out of sync with each other. `printRender` reads the live table rows directly (not the field's hidden snapshot-mirror input), omits a row only if its Size is empty *and* nothing was scored, renumbers surviving rows sequentially, and omits the whole section if every row was blank. The Scoring Key itself is deliberately **not** printed (screen-only) — the table's own Total Points/TIRADS Level columns already carry the scored outcome, and dropping the key helps a sheet fit on one printed page.
- **Carotid's Vessel Panels** (`data/carotidSheet.js`): a `layout: 'table'` section (see `js/formRenderer.js` above) with a `printRender` mirroring the on-screen Right/Left rows, using a shorter `printTableColumns` header set (10 data columns is tight on a printed page) distinct from the fuller on-screen `tableColumns` — a one-off array scoped to this section rather than a new generic per-field print-label flag, since this is the first time the need has come up. Its "is there anything to print at all" check treats a field still sitting at its own `defaultValue` (Stenosis Location, defaulted to ICA) as *not* real data — otherwise Stenosis Location's default would make the section look non-empty on a completely untouched sheet, since that default is applied at render time before the tech touches anything (the same category of bug the Physician Name dropdown's default caused for the unsaved-changes snapshot, fixed independently here since this is a section-omission check, not that mechanism).
- **Carotid's Reference Table**: a `static-table` field (see `js/formRenderer.js` above) — pure on-screen reference, its values transcribed verbatim from the practice's own paper form (`images/Carotid_Tech_Sheet_Reference.jpg`) rather than a generic clinical standard, since the two can differ (this practice's ICA PSV thresholds are 180/230 cm/s, not the commonly-published 125/230 SRU consensus figures). Deliberately not derived from any live field, unlike Thyroid's Scoring Key.
- `js/confirmModal.js` — the generic confirmation modal (static blank markup in each HTML shell: `#confirmModal`/`#modalTitle`/`#modalMessage`/`#modalCancel`/`#modalConfirm`, filled in per invocation — not a native `confirm()`). `initConfirmModal()` wires the static Cancel/Confirm buttons once per page; `showConfirmModal({ title, message, confirmLabel, onConfirm, onCancel })` sets the text and swaps both callbacks — `onCancel` (optional) fires on Cancel *or* Escape, used by the nav dropdown to revert its selection when the user backs out rather than leaving it visually pointed at a sheet it didn't navigate to. Shared by the Clear button and the nav's unsaved-data guard, each with their own wording.
- `js/clearForm.js` — `clearSheet(schema)` walks `flattenFields` to blank every field and re-collapse revealed sections, dispatching `diagram`/`dynamic-table` fields to `resetDiagram`/`resetDynamicTable` rather than touching their DOM directly; `initClearButton` wires the Clear button to `showConfirmModal`, then re-baselines (see below) once cleared. Also owns the unsaved-changes check: `recordInitialState(schema)` snapshots every field's `getDisplayValue` (via `JSON.stringify`, keyed by field id) once right after the sheet renders, and `hasUnsavedChanges(schema)` re-snapshots and compares against that baseline — deliberately a snapshot diff rather than field-by-field "is this empty", since the latter previously misfired on fields with a non-blank `defaultValue` (the Physician Name dropdown) even on an untouched page.
- `js/nav.js` — `initNav(schema, currentSheetId)` renders the persistent sheet-switcher into `#navMount` from `data/sheets.js` as a single `<select>` (stays compact as more sheets are added, rather than a growing row of links/buttons), pre-selected to the current sheet. Its `change` handler checks `hasUnsavedChanges(schema)` and, if there's unsaved data, runs `showConfirmModal` with "unsaved data" wording (reverting the select back to the current sheet via `onCancel` if the tech backs out) before navigating via `window.location.href` on confirm — per `DESIGN.md` §5, switching sheets is a normal page navigation, not a JS state swap.
- `js/initSheet.js` — `initSheet(schema, sheetId)`: the full per-page bootstrap sequence (`renderSheet`, `recordInitialState`, `initReveals`, `initComputedFields`, `initDiagramMarkup`, `initDynamicTables`, `initConfirmModal`, `initClearButton`, `initNav`, wiring the Print button to `openPrintView`) — `recordInitialState` runs immediately after `renderSheet` so the unsaved-changes baseline reflects the as-loaded DOM, defaults included. This is what `js/app.js`/`js/thyroidApp.js`/`js/carotidApp.js` each call.

When adding a field type, reveal pattern, or print behavior, extend the generic modules above (or use the `printRender`/`printRowCount` hooks for something genuinely sheet-specific) rather than special-casing any one sheet's schema inside a shared file — that reuse is the whole point of the schema-driven design.

## Project Purpose

Internal web app for ultrasound technologists to fill out digital "tech sheets" during patient studies, replacing paper/PDF forms currently in use. The form must respond to inputs dynamically (revealing conditional fields), generate a downloadable/printable PDF, and eventually support a preliminary interpretation workflow for physicians to sign off on or edit.

Phase 1 scope was the **Abdominal Ultrasound** sheet (complete); the **Thyroid Ultrasound** sheet (Demographics, Lobe Measurements with live-computed Volume, Appearance, Diagram Markup, Nodule Table with live TIRADS scoring, Comments, Interpretation, per `DESIGN.md` §8–9) and the **Carotid Ultrasound** sheet (Demographics, Right/Left Vessel Panels with a live-computed CA/CCA Ratio, Diagram Markup, a static clinical Reference Table, Comments, Interpretation, per `DESIGN.md` §10) are now also complete. The architecture anticipates ~15 total sheet types (8 common) being added over time — an Arterial sheet (per `DESIGN.md` §8's Diagram Markup section) is the next one referenced but not yet built.

## Design Reference

Full design spec lives in [DESIGN.md](DESIGN.md). Key points future work must respect:

- **Architecture**: Favor a reusable field/section component pattern over one-off hand-coded HTML per form, so future sheet types can be added primarily as configuration/content rather than new engineering.
- **Color palette**: dark charcoal/navy background (`#26335E`), lighter card background (`#394D8F`), soft white text (`#E9EBF0`), muted gray-white secondary text (`#AFB0B3`), amber accent (`#FAA946`), red error/validation (`#9E0202`).
- **Typography**: system font stack — `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif`.
- **Layout**: sections per organ/finding area; related measurements for one organ grouped in a horizontal row within a card; standalone measurements as single fields; numeric inputs use `<input type="number">` with the unit shown in the label, not typed by the user.
- **Conditional field reveal timing**: number fields reveal dependents on **blur** (not while typing); selection fields (dropdown/radio/checkbox) reveal dependents on **change** (immediately). Revealed fields animate in smoothly, no jump/reflow.
- **Field-specific rules**: Aorta dissection/iliacs fields reveal if Prox/Mid/Dist ≥ 3.5cm (any segment, checked on blur of any of the three) and **re-hide reactively** if a later edit brings all three back below the threshold — confirmed with the user over `DESIGN.md`'s more ambiguous "reveal ONCE" wording, which read as a single combined trigger check across the three fields rather than a permanent one-time reveal; Sex field has a fixed option list including a free-text reveal for "Other"; Prior Study's date field is a real `date` input (single specific date only, not a range/interval); Physician Interpretation's toggle reveals a physician-name dropdown (defaulted to "Other - enter manually", which reveals a manual-entry field) plus an impression textarea — see `js/printView.js` above for how this feeds the printout.
- **Print/PDF export**: opens a new window/tab with a clean print-formatted HTML/CSS view of the filled data and calls `window.print()` — do not use a JS PDF-generation library. The window stays open (doesn't auto-close) so the tech can review before saving/closing. Layout is intentionally denser than the on-screen form (see `js/printView.js` above for the current column/section structure) — the on-screen editing experience itself is never touched to achieve this.
- **Print column layouts must avoid CSS `column-count`**: confirmed via real iPad testing that `column-count` collapses to a single column specifically during iOS Safari's actual print/PDF export pass, despite looking correct in on-screen preview (including the interactive print-preview panel) — a known WebKit bug (see `js/printView.js`'s Findings-column implementation for the working alternative and links). Flexbox-based column layouts were not affected. Prefer flexbox for any future print-layout column work in this project, and treat `column-count` as a known risk specifically in print contexts unless testing shows otherwise.
- **Clear button**: clears all fields, gated behind the shared confirmation modal (`js/confirmModal.js`, not a native `confirm()`).
- **Nav & multi-sheet switching**: a persistent nav (`js/nav.js` + `data/sheets.js`) is a `<select>` dropdown listing every sheet page, pre-selected to the current one — deliberately a dropdown rather than a row of links/buttons, to stay compact as more sheets are added. Each sheet is a standalone HTML page — switching is a real page navigation (`window.location.href`), not a JS state swap. Before navigating away from a sheet with unsaved changes (`hasUnsavedChanges` in `js/clearForm.js` — a snapshot comparison, not a "which fields are non-empty" check), the same shared confirmation modal used for Clear intercepts the dropdown's `change` event with "you'll lose unsaved data" wording instead, reverting the selection if cancelled; an untouched sheet navigates immediately with no prompt.
- **Diagram Markup** (`DESIGN.md` §8, `js/diagramMarkup.js`): shared across any sheet with a `type: 'diagram'` field. Freehand red strokes only, via Pointer Events (not separate mouse/touch handlers); each stroke is a discrete undoable unit; Enable Markup gates drawing and auto-unchecks on an outside click/touch; print flattens the canvas to a static image via `toDataURL()`, preserving the red (a deliberate exception to print-color-reduction, since the color is functionally load-bearing, not decorative).
- **Explicitly out of scope**: auto-population of Technologist Comments from measurement thresholds (planned Phase 2 — do not implement yet, but the field must exist as a plain textarea), sheet types beyond Abdominal/Thyroid/Carotid, and any backend/database/account system or persistence (export is print/PDF only).

When scaffolding the project or making structural decisions, prioritize the reusable field/section component pattern called out above — it's the core architectural constraint for this codebase.
